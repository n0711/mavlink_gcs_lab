# Architecture

MAVLink GCS Portfolio is a small receive-only desktop prototype.

```text
Flutter Linux UI
→ flutter_rust_bridge
→ Rust backend
→ UDP JSON telemetry adapter on 127.0.0.1:16000
→ sample telemetry sender or optional MAVLink-to-JSON bridge
```

## Flutter

Flutter owns the dashboard, tabs, offline parameter workflow, and operator-facing
status panels. The UI consumes typed telemetry snapshots generated by the Rust
backend.

## Rust

Rust owns the current receive-only telemetry boundary:

- `rust/src/api/simple.rs`: bridge entry point
- `rust/src/telemetry/link_manager.rs`: adapter identity and diagnostics
- `rust/src/telemetry/udp_stream.rs`: UDP receive loop
- `rust/src/telemetry/parser.rs`: JSON-to-snapshot conversion
- `rust/src/telemetry/snapshot.rs`: Flutter-facing snapshot types

The current source is UDP JSON, not native MAVLink. This keeps the portfolio
demo easy to run while leaving a clear place for a future Rust-native MAVLink
receiver.

## Telemetry Contract

The adapter listens on `127.0.0.1:16000`. Payload fields are optional and
generic:

- `position`: latitude, longitude, altitude
- `attitude`: roll, pitch, yaw
- `system`: armed state, mode, battery
- `gps`: fix type, satellites, HDOP
- `telemetry`: message counts, rates, freshness
- `status_text`: optional diagnostic text

Malformed JSON becomes a safe fallback snapshot and increments the parse error
count. It never creates a command path.

## Bridge Code

`flutter_rust_bridge` generated files are checked in. If the Rust API changes,
regenerate the bridge with the matching project toolchain or keep any manual
edits mechanical, field-order preserving, and verified by tests and a Linux
debug build.
